# User journeys and recovery

| Journey                 | Main path                                                                                                                                                | Failure/recovery behavior                                                                                                                                         |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Buy a ready-made design | Social deep link → product/template → select full variant → preview/price → review → persist request → WhatsApp → customer sends → staff confirms        | Disabled template/variant explains alternatives; changed price requires renewed review; cancelling WhatsApp leaves an unconfirmed request                         |
| Customize a template    | Browse category → choose template → copy into own document → edit both sides → review warnings → order                                                   | Template source never mutated; deleted/updated template does not rewrite saved customer revisions                                                                 |
| Start from blank        | Select garment → empty sides → add image/text/shape → transform/layers → review physical print area → save/export → order                                | Missing print specification prevents production validation; low resolution gets actionable warning; clipping cannot silently discard art                          |
| Return to work          | Open site → inspect two local project summaries → choose restore → validate schema/assets → resume                                                       | Corrupt/unsupported file leaves current work intact; quota denial shows unsaved state and export; private browsing or cleared storage cannot be promised recovery |
| Create third project    | Two saved slots → request new/imported project → identify least recently edited slot → choose export-and-replace, replace, or cancel                     | Existing two remain until replacement and new assets commit atomically; failed export/write never evicts old slot                                                 |
| Send order later/retry  | Review existing completed request → retry WhatsApp from visible button or copy reference/link/message                                                    | Repeated same request returns same order; fresh price/variant/design creates a new reviewed intent; expired share link has a bounded authorized renewal path      |
| Staff manages orders    | Sign in → review request/design/quote → match actual inbound WhatsApp contact → pending confirmation → manually confirm → production → ready → delivered | Permission denial does not reveal data; invalid transitions rejected; cancellation records actor/reason; draft never counts as confirmed revenue                  |
| High demand             | Staff publishes notice/lead time or pauses orders → shoppers still browse/edit/export                                                                    | Backend also checks pause at intent/finalization; in-flight request handling is explicit in ordering design                                                       |

Editor warnings stay attached to the affected side/object. Switching sides or rotating a device must not reset edits. Mobile back/navigation and download failures offer recovery; opening an external app must not discard the last saved revision.

Offline editing/restoration is a recommended enhancement where assets are already available, not a promise of a full offline storefront. Ordering requires a live authoritative backend. Do not show a successful local save before the storage transaction finishes.
