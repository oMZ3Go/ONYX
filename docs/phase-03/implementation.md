### Floating release diagnosis and pointer lifecycle

The old implementation remembered a drag with `ignoreClick`, then cleared it using `setTimeout(..., 0)` on pointer release. The document's click listener had no record of where the press began. A later compatibility click retargeted to the newly exposed canvas could therefore dismiss a panel whose gesture started inside. Initial ordinary mouse and Chromium touch attempts passed; the failure was reproduced deterministically with an actual captured mouse drag followed by its deliberately delayed/retargeted click. The pre-fix regression failed with `data-panel-open="false"`. This establishes the vulnerable event sequence without claiming every native drag reproduced it.

The document now records the press origin in the capture phase. An inside-origin press or active panel gesture cannot trigger outside dismissal, regardless of click delivery timing. A new pointerdown resets the gesture-click guard, so the very next genuine outside click still works. There is no dismissal timer. Only the dedicated move/resize handles capture pointers; ordinary tabs, artwork buttons and list scrolling retain their own behavior. The active gesture records its pointer ID and capture owner, rejects unrelated/secondary pointers, commits bounded position/height on pointerup, and rolls back live changes on pointercancel/lost capture. Capture and listeners are released on cancellation, blur, mode changes, suspension and unmount.

`WorkspaceState` separately contains view, grid visibility, library category/section, inspected artwork, inspector tab and open responsive panel. Camera is separate `{zoom, x, y}` state; panel dimensions/docking are separate persisted UI preferences, alongside the independent theme preference. None of these changes mutate the document or create a save/dirty event. The validated garment variant selection is the only implemented document mutation boundary; currently there is one valid variant.

The top status remains “Not saved yet.” Save, Continue, artwork placement, Undo and Redo remain disabled with explanations. Upload accepts no files; no project is persisted. Appearance uses a cookie; panel layout uses a separate versioned localStorage key. Neither stores editable design data.
